1.개요

2024년 3월부터 5인 규모 아웃소싱 회사에서 프론트엔드를 맡고 있습니다. 기술 선택과 초기 환경 구축부터 배포, 운영, 인수인계까지 14 번의 풀사이클 개발을 경험했습니다. 그중 4개 프로젝트는 100% 주도하여 완성했습니다. 대표작으로는 2년 4개월 동안 운영 중인 골프 티켓 예매 플랫폼 eticket, 4개월 동안 130개 페이지를 홀로 구축한 AI 상담 플랫폼 onui, 앱스토어와 플레이스토어 출시 경험을 쌓은 건설업체연결 서비스 쓸모, 2024 스마트앱어워드 대상을 받은 L.Scan입니다.

소규모 프론트엔드 팀에서 프로젝트의 파편화된 일부가 아닌 '전체 생태계'를 다루는 경험을 쌓았습니다. 기술 선택과 초기 세팅을 시작으로 개발, 배포, 운영, 그리고 인수인계까지 서비스의 시작과 끝을 모두 직접 경험했습니다. 특히 법인 설립부터 함께한 1호 직원으로서 TIPS 2024, 청년사업패키지, 재도전패키지 선정 과정에 참여했습니다. 심사 제출용 웹 애플리케이션 제작과 연구노트 작성을 맡아 회사의 주요 성과를 기술적으로 단단히 받쳤습니다.

외주 환경 특성상 골프 티켓 예매부터 전문가 상담, 중장년 채용, e스포츠, 건설 업체 매칭, 인플루언서 광고, B2B 관리, 안전 점검까지 매우 넓은 스펙트럼의 도메인을 경험했습니다. 생소한 비즈니스 로직과 도메인 지식을 빠르게 파악해 완성도 높은 서비스로 구현해 내는 역량을 단단히 다졌습니다. 동시에 eticket 서비스를 2년 4개월간 장기 운영하며, 단발성 구축을 넘어 한 서비스를 깊이 있게 고도화하고 유지보수한 경험까지 두루 갖추었습니다.

2.강점

2.1.세팅부터 배포까지, 10번 이상 검증된 완결성과 생산성

기여도 100%로 완수한 프로젝트만 4개입니다. PUBG(67커밋), 한국 중장년 협회 사이트(31커밋), 쓸모 앱(48커밋)을 단독 개발했고, onui는 총 434개 커밋 중 432개를 전담 작성했습니다. 여기에 직접 초기 세팅을 맡은 eticket(1,173커밋)과 커넥티드456(728커밋)이 더해져 높은 개발 밀도를 증명합니다.

이러한 경험의 핵심은 빠른 몰입과 실행력입니다. onui는 4개월 만에 130개 페이지를 홀로 구축해 냈고, PUBG는 대회 시작 일주일 전에 착수해 7일 만에 MVP를 실서버에 배포했습니다. 썸띵 역시 2개월 만에 297개 커밋을 작성하며 신속하게 결과를 만들어냈습니다.

2.2. 제품 기능과 개발 생산성, 양축을 아우르는 AI 활용

AI를 서비스 기능으로 구현하는 데 그치지 않고, 개발 워크플로우 자체에 녹여내어 생산성을 극대화한 경험이 저의 두 번째 강점입니다.

AI 적용 대표작은 onui입니다. 상담 챗봇부터 사전 체크리스트 생성, STT 기반 상담 요약, 전문가 리포트 초안 작성, 비식별 데이터 기반 유사 사례 검색까지 상담의 전 과정에 AI를 결합했습니다. more에서는 모임 정보를 분석하여 해당 모임의 성향을 파악하는 질문 생성과 신뢰도 리포트 작성 등에 AI를 도입하였습니다.

업무 측면에서는 관리자 페이지 생성 워크플로우를 자동화했습니다. 공통 컴포넌트를 미리 구축한 뒤, 화면 목록과 유저 플로우 문서를 AI 모델에 학습시켜 CRUD 기본 아키텍처를 빠르게 추출하고 여기에 해당 프로젝트의 핵심 기능을 얹어 완성하는 방식입니다. 이를 통해 과거 짧게는 일주일, 길게는 한 달이 소요되던 관리자 페이지 구축 기간을 2~3일로 획기적으로 단축했습니다.

2.3.반복되는 경험을 재사용 가능한 기술 자산으로 전환

프로젝트마다 유틸리티 코드를 반복해서 작성하고 복사·붙여넣는 피로감을 해결하기 위해 사내 라이브러리인 @freewier2/things를 구축했습니다. 소스코드 템플릿에 단순히 포함시키는 방식 대신, npm private 레지스트리를 통해 배포함으로써 어떤 프로젝트든 간단한 패키지 설치만으로 공통 자산을 일관되게 공유하고 활용할 수 있도록 설계했습니다.

여기서 한 걸음 더 나아가, 백엔드 API 스펙 변경에 대응하는 수고를 덜고자 Swagger 코드 생성 커스텀 템플릿을 도입했습니다. API 규격에 맞춰 클라이언트 코드를 수동으로 작성하거나 수정하던 공수를 없애고 자동화한 결과, 초기 프로젝트 셋업부터 API 연동 기초 작업까지 과정을 30분 이내로 단축하며 팀 전체의 개발 리소스를 대폭 절감했습니다.

2.4. 웹·앱 실서비스 출시 및 크로스 플랫폼 구축

웹뿐만 아니라 모바일 앱 생태계까지 커버리지를 넓혀 실제 마켓 배포 및 운영 전 과정을 완수했습니다. 쓸모 프로젝트에서는 하나의 서비스를 웹과 모바일 앱으로 각각 구축하여 App Store와 Google Play Store에 성공적으로 배포했습니다. 한편, L.Scan에서는 기존 웹 자산을 하이브리드 형태로 패킹하여 크로스 플랫폼 앱으로 효율적으로 빌드하고 출시를 끌어냈습니다.

단순한 1회성 출시 경험에 그치지 않고, 네이티브 앱과 웹뷰 연동 과정에서 발생한 노하우를 바탕으로 React Native 공통 템플릿을 제작했습니다. 이를 통해 반복적인 웹뷰(WebView) 브릿지 설정, 네이티브 권한 처리, Push 알림 등 자주 쓰이는 핵심 모듈을 자산화하여, 향후 하이브리드 앱 프로젝트 착수 시 개발 공수를 대폭 줄이고 안정성을 확보할 수 있는 체계를 만들었습니다.

3.프로젝트

3.1.eticket — 골프 티켓 예매 플랫폼

골프 대회 일정 안내, 티켓 예매 및 결제를 주력으로 제공하는 서비스입니다. 주 사용자는 골프를 즐기는 중년층으로 회원 계정 6,591개를 보유하고 있습니다. 입사 후 최초로 초기 세팅부터 전담한 프로젝트이자, 2년 4개월간 지속 운영 중인 대표 작업입니다. 전체 프론트엔드 기여도 중 가장 높은 1,173커밋(동료 479커밋, 전임자 406커밋)을 기록하며 개발과 유지보수를 주도했습니다.

단계별 개발 이력

1차 개발(2024.06 ~ 2024.11 / 515커밋)에서는 초기 아키텍처 구축, MVP 개발 및 핵심 예매·결제 플로우를 완성했습니다. 2차 개발(2025.02 ~ 2025.09 / 289커밋)을 통해 신규 기능 확장과 관리자 시스템 재정비를 진행했고, 3차 개발(2026.01 ~ 2026.04 / 369커밋)까지 안정적으로 마무리한 후 현재는 서비스 운영 및 기능 고도화 대응을 전담하고 있습니다.

서비스 확장에 맞춘 구조 개선 및 기술 부채 해결

초기 단계에 작성한 코드의 기술 부채를 해결하기 위해, 신규 기능 개발 시 관련 레거시를 함께 개선하는 방식을 취했습니다. 특히 서비스의 핵심인 결제 로직을 깔끔하게 구조화하여, 결제 실패나 오류 위험을 줄이고 시스템 안정성을 확보했습니다.

또한 잦은 요구사항 변경에 유연하게 대응하고자 당장의 기능 구현을 넘어 확장성을 고려한 컴포넌트·타입 구조를 구축했습니다. 그 결과, 조건이 수시로 바뀌는 상황에서도 기존 기능의 사이드 이펙트를 최소화하며 개발 속도를 끌어올렸습니다.

Sentry 기반 실시간 에러 모니터링 및 추적 체계 구축

초기에는 프로덕션 에러를 CS 접수에만 의존해 파악하는 수동적인 구조였습니다. 이를 개선하기 위해 Sentry를 도입하고 Slack 알림을 연동하여 실시간 에러 감지 환경을 구축했습니다.

이를 통해 장애 인지 속도를 크게 줄였을 뿐만 아니라, 기존 비개발자 사용자의 "~기능이 안 된다"는 식의 모호한 표현에 기대지 않고, 에러 발생 API, 스택 트레이스, 사용자 행동 로그(replay)를 정밀하게 추적할 수 있게 되었습니다. 결과적으로 이슈 원인 파악의 해상도를 높이고 디버깅 및 해결 시간을 단축했습니다.

관리자 페이지 컨벤션 표준화 및 리팩터링

여러 개발자가 시기를 달리하여 구축하며 발생한 관리자 목록 페이지들의 UI·동작 파편화 문제를 해결했습니다. 342줄 규모의 docs/admin-state-convention.md 문서를 통해 상태 관리 및 UI 동작 명세를 표준화하고, 이를 기준 삼아 기존 목록 페이지 전체를 통합 리팩터링했습니다.

이 작업을 통해 관리자 페이지 전반의 UX 일관성을 확보했을 뿐만 아니라, 여기서 확립된 컨벤션은 향후 문서 기반 관리자 페이지 생성 워크플로우를 구축하는 핵심 기초 자산이 되었습니다.

3.2.onui — AI 기반 전문가 상담 플랫폼

특정 분야 전문가와 이용자를 연결하여 1:1 상담(대면·전화·화상)과 세미나 개최 및 수강을 제공하는 서비스입니다. 4개월(2026.05 ~ 2026.09)의 단기 프로젝트 기간 동안 총 434커밋 중 432커밋(99%)을 단독으로 주도하여 프론트엔드 아키텍처와 AI 연동 전반을 구축했습니다.

LiveKit 기반 자체 호스팅 화상 상담 구축

외부 화상 SDK의 비용 및 커스텀 제약 한계를 극복하기 위해 LiveKit을 직접 자체 호스팅하여 화상 상담 환경을 구축했습니다. 화상 통화, 실시간 화면 공유, 채팅, 음성의 텍스트 자동 변환(STT), AI 분석 기능까지 하나의 통합된 상담 세션 흐름 안에 매끄럽게 녹여냈습니다.

상담 전후 흐름 전반에 걸친 LLM 및 RAG 도입

사용자 유입부터 상담 사후 관리까지 전 과정에 AI 기능을 유기적으로 배치하여 서비스의 자동화와 고도화를 이끌어냈습니다.

기능 입력 산출과 쓰임
AI 챗봇 선택한 분야 + 이용자 질의 참고용 초기 상담 답변 제공 및 동일 대화 기반 전문가 추천
사전 체크리스트 상담 주제, 직전 답변 내용 맞춤형 꼬리 질문 생성 및 매칭·상담 신청의 기초 자료 활용
상담 요약 화상 음성 실시간 텍스트 기록 이용자 및 관리자가 사후에 열람하는 핵심 상담 노트 생성
리포트 초안 전체 상담 기록 데이터 핵심 요약 및 조언 초안 작성 후 전문가 검토를 거쳐 최종 리포트 확정

OCR 기술과 정부 공공 API를 연동하여 복잡한 인증번호 확인 절차를 간소화하고, 단 한 번의 촬영으로 다중 인증번호를 판정하는 효율성과 직관적인 UI/UX를 인정받아 현장 업무 기여도 측면에서 우수한 평가를 거두었습니다. 서비스 전반의 구축 성과 중 관리자 페이지와 사용자 웹 화면 전반의 개발을 담당했습니다.

대시보드 영역에서는 기간 조회, 품목별 유효·비유효 집계, 추이 차트(chart.js)를 API와 연동했습니다. 요청 및 품목(전기용품, 생활용품, 어린이용품, 화학제품, 전파적합성) 관리 페이지의 목록, 필터, 상세 조회 기능을 구축하고 기록 삭제 및 외부 인증 검색 링크를 연결했습니다.

운영 관리 부문에서는 환경 설정(담당자, 인증코드, 월별 OCR 한도 관리)과 공지사항·이용가이드 CRUD 기능을 연동했습니다. 또한 목록 필터 결과의 엑셀 다운로드 API 연동, 조회 조건의 URL 쿼리 파라미터 동기화(새로고침 및 공유 시 상태 유지), 한국 표준시(KST) 시간 표기를 일괄 적용하여 사용자 편의성을 높였습니다.

사용자 화면 핵심 플로우 고도화 및 인터랙션 정비

파일/이미지 조회 선택 흐름을 매끄럽게 다듬고, 결과 요약의 유효성 판정 로직, 상세 화면, 완료 상태 UI를 개선했습니다. 이력 조회 화면의 로딩 및 동작을 최적화하는 한편, 하드코딩된 값을 제거하고 토스트 메시지 시스템을 도입해 사용자 피드백을 강화했습니다.

시스템 공지 노출 및 관련 가이드 페이지 연동을 손봤으며, 로그인 화면의 예외 처리를 고도화하고 API 조회 요청 시 기기 고유 식별 키(Device Key)를 동반하도록 구현하여 추적성과 보안성을 높였습니다.

4.공용 자산

4.1.@freewier2/things — 사내 공용 라이브러리

프로젝트 간 반복되는 필수 유틸리티 및 커스텀 훅의 중복 구현을 방지하고 프론트엔드 생산성을 극대화하기 위해 구축한 사내 공용 라이브러리입니다. (51 / 98 커밋, 52% 기여)

하위 호환성 유지 및 Breaking Change 방지 가이드는 수립

useMediaQuery 훅 개발 과정에서 의존 유틸리티 수정으로 인해 기존 사용 중이던 프로젝트에서 하위 호환성이 깨지는 타입 에러가 발생한 사례가 있었습니다.

즉시 해당 변경을 롤백하여 안정성을 확보함과 동시에, 라이브러리 업데이트 시 기존 API 배포 계약을 준수하도록 breaking-changes.mdc 규칙 가이드라인을 정립했습니다. 패키지 배포 시 하위 호환성 검증과 책임감 있는 버저닝의 중요성을 체득하는 계기가 되었습니다.

Swagger 기반 커스텀 API Client Generator 및 컴포넌트 모듈화

Swagger 자동 생성 API 클라이언트 JWT 토큰 재발급 로직과 사내 API의 GET 요청 쿼리 파라미터 구조(filter 래핑 규칙)를 커스텀 템플릿 형태로 내장시켜 매 프로젝트마다 반복되던 상동 보일러플레이트 코드를 수십 줄 이상 감축했습니다.

또한, 관리자 페이지 전반에서 자주 쓰이는 위지윅 에디터(네이버 스마트에디터) 모듈을 things-smart-editor로 별도 분리하여 라이브러리화함으로써 신규 프로젝트 도입 시 연동 공수를 대폭 줄였습니다.

5.AI를 업무에 적용한 방식

5.1.관리자 페이지 자동 생성 워크플로우

다수의 프로젝트를 수행하며 공지사항, 배너, 유저 관리, 권한 관리 등 대부분의 백오피스에 반복되는 CRUD 기능과 패턴을 파악했습니다. 백오피스 프레임워크가 지닌 효용성에 착안해, 핵심 관리자 UI 구조를 체계화했습니다.

디자인 화려함보다 정보 구조와 사용성이 중요하다고 판단하여, 사이드바, 필터, 상세 페이지, 표준 테이블 레이아웃 규칙을 컴포넌트 단위로 사전에 정의해 둡니다. 이후 프로젝트별 사용자 화면 목록, 유저 플로우, 기획 문서를 AI 프롬프트와 함께 전달하여 기본 CRUD 구조를 신속하게 초벌 생성합니다.

5.2.디자인과 개발의 순서를 뒤집은 역발상 프로세스

이 방식으로 관리자 페이지 MVP를 선제적으로 구현함에 따라, 전통적인 '디자인 시안 합의 후 개발 착수'라는 순서를 정반대로 뒤집었습니다. 프론트엔드 환경에서 구현된 MVP 산출물을 먼저 도출한 뒤, 이를 디자인 검토용 시안으로 역제공하는 워크플로우를 도입했습니다.

구현된 웹사이트를 피그마로 전환하는 과정에서는 동료가 개발한 screenshot-to-figma 도구를 적극 활용했습니다. 설정 파일만 변경하면 다른 프로젝트에도 즉시 적용할 수 있는 이 도구를 통해 전체 페이지 화면을 피그마로 손쉽게 동기화했습니다.

이후 클라이언트가 요청한 브랜드 컬러, 컴포넌트 여백 등 세부 피드백을 수정한 뒤 최종 전달까지 매끄럽게 마쳤습니다.

5.3.본인의 AI 활용 원칙

AI가 생성한 코드는 반드시 직접 검증하며, 코드가 길면 요약과 구조 분석을 함께 요구합니다. 검증 없이 쌓인 코드는 추후 단순한 수정조차 스스로 하지 못하고 다시 AI에 의존하게 만드는 악순환을 낳으며, 이는 심각한 유지보수 공수 증가로 이어집니다. AI가 코드를 작성하더라도 개발자가 완전히 이해하고 통제할 수 있는 범위 내에 두어야 하며, 주도권을 잃지 않는 명확한 원칙을 바탕으로 활용합니다.
